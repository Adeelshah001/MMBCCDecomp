## 0x080224E4 / 0x08021B3C — BlendCopy (206 B, BLOCKED, 94 diffs best)

15-bit color blenders. Twins confirmed identical except 2 bytes (the `bl Memcpy16` encoding at file offset 57-58).

### Progress (104 → 94 diffs)
Wave 27-C left a systematic low-reg r3↔r4 swap: ROM av→r4/mask-copy→r3/b1→r3 vs mine av→r3/mask-copy→r1/b1→r4.

**Decisive new idiom — clobber-reservation on the low-reg thief:**
```c
av = *(u16 *)srcB;
__asm__ volatile("" : : "r" (av) : "r3");
```
The input-form empty asm with an r3 clobber denies r3 to `av`'s entire live range (local-alloc colors the qty once per block). `av` falls to r4 (ROM-exact). This single change cascades correctly: a2→r4, b1→r3, s1→r3, loop-tail temp `mov r3,sl` — all ROM-exact. (The `+r` form was worse at 137 diffs; the input `"r"` form gives 94. The v12 "clobber" from wave27-C was never actually saved to its file — v12 was byte-identical to v11, so this angle was genuinely untried.)

Note: this is distinct from pin-the-thief (which removes a reg from the pool function-wide). The clobber only denies the reg at the qty's live range, leaving r3 available for b1/s1/loop-temp later in the block.

### Remaining wall: reload's register choice (3 copies)
Disassembly of the RTL (`-da`, `_vc.i.lreg`) proves the three mismatched copies are **generated by gcc's reload pass, not local-alloc**:
- `av = *(u16*)srcB` with srcB in ip → RTL keeps `(mem:HI (reg:SI 12))`; reload emits `mov r7,ip` (ROM: `mov r2,ip`).
- `a0 = av & mask` with mask in r9 → RTL keeps `(and (reg 42) (reg:SI 9))`; reload emits `mov r1,r9` (ROM: `mov r3,r9`).
- `bv = *(u16*)srcA` with srcA in r8 → reload emits `mov r2,r8` (ROM: `mov r7,r8`).

Empirically, reload picks the **numerically-first free low reg** (verified across all 5 reloads in the loop: r7/r1/r2/r3/r7 vs ROM r2/r3/r7/r3/r7 — the two that match are where the preferred regs were occupied). At each of the 3 mismatched points, r1/r7/r2 are free because no live pseudo occupies them, so reload takes them. The live set at those points is fixed by ROM's instruction order (only av/a0 live at the first `ands`), so the free set cannot change without adding locals or reordering instructions — both forbidden (new locals perturb the fragile high-reg r8/ip/r9 assignment; reordering breaks ROM's byte order).

**Tried and failed for the reload:**
- r1/r2 clobber-denial after `a0 = av & mask` → splits the mask-copy qty into two (a0-only part stays r1, rest moves to r2); worse (102 diffs).
- Explicit `int mc1/mc2` mask-copy variables (function-scope and loop-scope) → breaks high-reg allocation entirely (srcA→sl, srcB→r8, blend→r7); 144-153 diffs.
- `int m = mask` variants → either optimized away (when mask=31 provable) or wrong position.
- `(mask & 0xffff)`, `mask & av` operand swap, u32 av, decl-order swaps → no effect (still r1).
- old_agbcc → identical r1 choice. `agbcc_arm` binary emits ARM-state code, unusable.
- Denying r3+r4 to av (av→r0) → mask reload still r1 (confirms numeric-first-free model).

## Idioms discovered
1. **Clobber-reservation for low-reg steering (new):** `__asm__ volatile("" : : "r" (v) : "r3")` denies r3 to `v`'s whole live range without removing r3 from the pool (unlike a pin). Use the input `"r"` form, not `"+r"`. This cracked the BlendCopy r3↔r4 swap (104→94).
2. **Reload vs local-alloc diagnosis:** when a copy `mov rX, <high>` resists all C steering, dump `-da` and check `_*.lreg`: if the RTL still has the hard reg operand at the `lreg` stage, the copy is reload-generated and follows numeric-first-free — a different (much harder) wall than local-alloc preference. Diagnose before fighting.
3. **High-reg fragility warning:** the mask→r9 pin-the-thief assignment (srcA→r8/srcB→ip/mask→r9) is destroyed by adding ANY new local to the function (observed: srcA→sl/srcB→r8/blend→r7). Do not add locals when this pin is in play; steer with clobbers instead.
